# Independent source-time strict output-pattern controls

`run.py` consumes an already-built native Linux x86-64 or AArch64 `mdslc-region`;
it does not configure/build the compiler or enumerate a production tile catalogue.
The connected lane issues explicit `3,5` and `5,3` requests from the same driver.
Additional requested `1,1` and `64,64` lifecycle controls cover the exact bounds;
the scalar-order/FMA cases include 65x129 outputs for full largest tiles and tails.
It separately checks original-witness identity, distinct derived/LLVM/object/DSO
bytes, parameter/source/target/toolchain inspection bindings, exact requested DSO
`NEEDED` entries, local issued leaf/wrapper definitions, and no dynamic leaf export.
Successful public `Result` mathematics alone cannot identify a private leaf.

`connected.mdsl` has 68 executed source cases: nonsymmetric rectangles and both
tile orientations' tails; full increasing-K/non-FMA discriminators; nonfinite,
subnormal and positive-zero behavior; input/late publication aliases; immutable
snapshots and owning observations; ordered late failures; nondefault caller
FP/errno restoration; zero M/N/K; and INT64_MAX empty/checked-overflow controls.
`same_value.mdsl` separately uses one immutable Value as both operands.
`rhs.mdsl` separately carries the first product on the RHS of a noncommuting
rectangular second product, with shifted late aliases and retained failure prefix.
The runner also executes explicitly selected publication forwarding and retains
stock default/automatic ownership when no source-time request is made.

The refusal lane checks canonical parameters, unsupported candidate/optimization/
object/program combinations, untrusted IR/manifest option refusals, no-overwrite
bundle file/directory/symlink controls, and an admitted negative `__has_include`
dependency naming the actual bundle's later-issued LLVM file. Failure must leave
no executable or newly owned bundle; caller-owned existing entries must survive.

`mutation_test.cpp` uses only the noninstalled deterministic phase seam. Valid
foreign tile LLVM/object/DSO and stale same-tile source DSO substitutions must fail
after capture, as must source/header changes at each phase, forged retained MLIR,
prepopulated stale manifests and a bundle directory/symlink race. The private
consumer is independently exercised with another authentic source, another entry
from the same source, mismatched candidate/optimization, worker contract, candidate
bytes, and installation sanitizer profile. These are falsifiers, not input APIs.

In a real ASan installation, `raw_asan_probe.cpp` deliberately violates the raw
leaf capacity precondition **outside the supported source-caller contract**. It
loads the exact source-issued DSO, obtains its load base from its ABI marker, and
calls the uniquely local wrapper whose independently parsed ELF64LE `LOCAL FUNC`
symbol lies in an RX load segment. The control requires `heap-buffer-overflow`
and a requested issued-leaf/DSO top-frame attribution, not merely a crash. This
does not add a production export, callback, importer, or authority route. A
separate host OOB control proves actual original-host instrumentation; LLVM
attributes or a driver banner alone are not sanitizer execution evidence.

`runner_test.py` tests malformed inspection/classifier and ELF controls using
synthetic data, separately from all physical execution. Its six unit tests are
not six source/target qualification cases. Existing relocated package acceptance
copies these source oracles and its inspector before producer removal, then
issues both requests after relocation/removal, checks all bundle/SDK hashes and
refuses a copied canonical public source header.

No performance, tuning, target-ISA execution, provider, GPU, SPIR-V, general
fusion, manual `-c` link, sandbox, or hostile future-loader qualification follows.
