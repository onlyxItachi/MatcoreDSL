## 4. Decision Function F Planner Integration

Derived from the 1,716-experiment corpus campaign, `evaluate_cpu_decision_function_f` routes linear algebra operations across five deterministic execution strategies:
1. **`direct_in_register_unroll`**: Selected for compile-time known static shapes ($M, N, K \le 16$). Eliminates 2,700 ns dispatch latency.
2. **`fused_vector_contract`**: Selected when activation epilogues (ReLU/Bias) are detected, accumulating and storing in-register.
3. **`parallel_multicore_streaming`**: Selected for Level-2 GEMV / GEVM streaming. Enforces the empirical memory bus saturation knee, capping active threads at $\le 8$ threads.
4. **`authenticated_cblas_5loop`**: Selected for large matrix footprints ($N \ge 64, M \ge 32$) to leverage cache-blocked OpenBLAS / BLIS execution.
5. **`llvm_direct_vector_reduction`**: Selected for degenerate DOT ($1\times 1\times K$) and outer products.

Validated by comprehensive unit tests in [`compiler/tests/runtime/cpu_planner_v3_test.cpp`](file:///c:/Users/hamza/Desktop/MatcoreDSL/compiler/tests/runtime/cpu_planner_v3_test.cpp).
